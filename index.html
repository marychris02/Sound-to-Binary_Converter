Explain It

  1. In your own words, how does your app change a sound wave into binary? Name the three steps.
    My app takes one full sound wave and measures how high it is at evenly spaced moments in time. Then it rounds each height to the nearest level, and finally it writes that level as 0s and 1s.
  2. Run Test A again with 2 bits, then 6 bits. Which gives more detail about the wave, and why?
    6 bits gives more detail. With 2 bits there are only 4 levels to choose from, but with 6 bits there are 64, so the binary follows the real height of the wave much more closely. The trade-off is that it uses more bits.
  3. Which test has the longest wavelength? How is wavelength connected to frequency?
    Test B has the longest wavelength (about 1.72 m) because it has the lowest frequency, 200 Hz. When the frequency goes up, the wavelength gets shorter, since wavelength is the speed of sound divided by the frequency.
  4. What was the hardest stage to build, and how did you fix it?
    The hardest part was the binary stage. My values kept coming out too short, like 10 instead of 010, so I added zeros in front until every value had exactly the right number of bits.
